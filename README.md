# repcollect — 复制采集后端

读取 UTF-8 JSON 数组（每项为一条完整 pgoutput 消息的小写偶数位 hex，无外层
封装），按 PostgreSQL 17 逻辑复制协议（协议版本 3，仅流式事务）从零解析、
采集，按提交序输出 `{xid, changes}` 数组。解析裁决全部手写，仅使用
`struct`/`base64` 等字节库。

## 入口

```
python3 repcollect.py INPUT OUTPUT
```

- `INPUT`：UTF-8 JSON 数组文件，每项是一条完整 pgoutput 消息的小写偶数位
  hex 字符串。
- `OUTPUT`：结果文件。**仅当整次输入成功时才原子替换**（同目录临时文件 +
  rename）；任何失败都保持旧输出不变。

退出码与错误报告：

| 退出码 | 含义 | stderr |
|---|---|---|
| 0 | 成功 | 空 |
| 1 | 输入被整次拒绝 | 出错消息的**零基消息号**；JSON 级错误为 `$` |
| 2 | 用法或 I/O 错误 | 人类可读说明 |

- 消息级错误（非法消息、协议串非 UTF-8、状态引用、hex 不合规）：stderr
  打印首个出错消息的零基消息号。
- JSON 级错误（输入非 UTF-8、JSON 解析失败、顶层非数组、数组项非字符
  串）：stderr 打印 `$`。
- EOF 时存在未闭合段：拒绝，打印打开该段的 `S` 消息的消息号。

## 输入契约

- 顶层为 JSON 数组；每项为小写偶数位 hex 字符串（空串、大写、奇数位、非
  hex 字符均按该消息号的非法消息拒绝）。
- 每项解码后恰为**一条完整消息**：1 字节标签 + 消息体，无长度前缀、无
  XLogData 等外层封装，不允许尾随字节。
- 仅接受标签 `S E c A p K r R I U D`，其余标签为非法消息。
- 协议中的 `String` 字段（命名空间、关系名、列名、GID）必须 NUL 终止且为
  合法 UTF-8，否则整次拒绝。元组 `t`/`b` 值按原值字节处理，不校验、不解码。

## 消息布局（PG17 协议 3，大端序）

| 标签 | 名称 | 体 |
|---|---|---|
| `S` | Stream Start | `u32 xid`, `u8 first`（仅 0/1） |
| `E` | Stream Stop | — |
| `c` | Stream Commit | `u32 xid`, `u8 flags`, `u64 commit_lsn`, `u64 end_lsn`, `u64 ts` |
| `A` | Stream Abort | `u32 xid`, `u32 subxid` |
| `p` | Begin Prepare | `u8 flags`, `u64 prepare_lsn`, `u64 end_lsn`, `u64 ts`, `u32 xid`, `str gid` |
| `K` | Commit Prepared | `u8 flags`, `u64 commit_lsn`, `u64 end_lsn`, `u64 ts`, `u32 xid`, `str gid` |
| `r` | Rollback Prepared | `u8 flags`, `u64 prepare_lsn`, `u64 end_lsn`, `u64 ts`, `u32 xid`, `str gid` |
| `R` | Relation | `u32 xid`, `u32 oid`, `str ns`, `str name`, `u8 replident`, `u16 ncols`, 然后每列 `u8 flags`, `str colname`, `u32 typeoid`, `i32 typmod` |
| `I` | Insert | `u32 xid`, `u32 oid`, `'N'`, TupleData |
| `U` | Update | `u32 xid`, `u32 oid`, [`'K'`/`'O'` TupleData], `'N'` TupleData |
| `D` | Delete | `u32 xid`, `u32 oid`, `'K'`/`'O'` TupleData |

TupleData：`u16 列数`，然后每列：

- `'n'`（null）/`'u'`（未变更 TOAST）：无负载；
- `'t'`（文本）/`'b'`（二进制，协议 3 新增）：`i32 长度` + 原值字节，长度
  须 ≥0 且不越界。

LSN、时间戳、`c/p/K/r` 的 flags 解析后忽略；`R` 的列标志、replica
identity、类型 OID/修饰符解析但不校验。

## 状态机规则

- **段**：`S` 开段、`E` 闭段；段不嵌套（段内 `S` 拒绝），`E` 须有打开段。
  事务可交错：不同顶层的段可交替出现。
- **首段标志**：新顶层 xid 的首个 `S` 标志须为 1，后续段须为 0。
- **段内/段外**：`R/I/U/D` 仅段内；`c/A/p/K/r` 仅段外。
- **XID 归属**：段内消息的 xid 等于当前顶层则归顶层；否则为其直属子事务
  （未知 xid 即绑定，保证无更深嵌套）。xid 不得跨顶层复用（顶层↔子事务、
  子事务↔子事务均拒绝），终结（提交/撤销/预备回滚/预备提交）后不得复用。
- **提交**：`c(xid)` 提交活跃顶层，按提交序追加输出。
- **预备**：`p(xid,gid)` 将活跃顶层置为已预备；此后仅接受 xid 与 gid 均
  匹配的 `K`（提交，产出输出）或 `r`（回滚，丢弃），其余引用一律拒绝。
- **撤销**：`A(xid, sub)` 两 xid 相同则撤销整个顶层；否则撤销指定直属子
  事务的 DML 并禁止再引用（重复撤销亦拒绝）。未知子 xid 先绑定后撤销。
  子事务随顶层终结而终结。
- **关系缓存**：`R` 按 OID 更新**全局**缓存，立即生效，回滚/撤销不撤销。
  DML 固定当时最近的 `R`；OID 未定义拒绝；新旧元组列数均须等于当时 `R`
  的列数。
- **EOF**：未闭合段拒绝；未终结（活跃或已预备）事务不输出；空输入得
  `[]`。

## 输出格式

JSON 数组，按提交（`c`/`K`）处理序排列：

```json
[
  {
    "xid": 1,
    "changes": [
      [3, "I", "<R 原文 hex>", null, [["t", "Yw=="], ["n"]]]
    ]
  }
]
```

每条 change 为 `[i, op, Rhex, old, new]`：

- `i`：该 DML 消息的零基输入号；
- `op`：`"I"`/`"U"`/`"D"`；
- `Rhex`：该 DML 当时最近 `R` 的输入原文（hex 字符串）；
- `old`/`new`：元组或 `null`——插入无旧元组、删除无新元组、无旧元组的
  更新，对应位置为 `null`；
- 元组按列序：`n`/`u` 为 `["n"]`/`["u"]`，`t`/`b` 为
  `["t", "<带填充 Base64 原值>"]`；值不解码，不补 TOAST。

被撤销子事务的 DML 从变更中移除，其余按接收序保留。

## 示例

输入（顶层 1 内子 2、3 各插入一次，`A(1,2)` 撤销子 2 后 `c(1)`）：

```json
[
  "530000000101",
  "5200000001000000647075626c69630074006400020169640000000017ffffffff0076616c0000000019ffffffff",
  "4900000002000000644e0002740000000161740000000162",
  "4900000003000000644e00027400000001636e",
  "45",
  "410000000100000002",
  "630000000100000000000000000000000000000000000000000000000000"
]
```

输出（仅保留子 3 的变更，`"Yw=="` 即子 3 插入的 `c`）：

```json
[
  {
    "xid": 1,
    "changes": [
      [
        3,
        "I",
        "5200000001000000647075626c69630074006400020169640000000017ffffffff0076616c0000000019ffffffff",
        null,
        [["t", "Yw=="], ["n"]]
      ]
    ]
  }
]
```

## 自写裁决点（假设）

1. “协议串非 UTF-8”仅指协议 `String` 字段（命名空间、关系名、列名、
   GID）；元组 `t`/`b` 值按原值字节 Base64，不做 UTF-8 校验（“值不解
   码”）。
2. hex 不合规（大写、奇数位、非 hex 字符）属于该消息号的非法消息，而非
   JSON 级错误；`$` 仅用于 JSON 级错误。
3. 未闭合段在 EOF 拒绝时，报告打开该段的 `S` 的消息号。
4. 多处错误时报告按接收序首个检测到的错误。
5. XID 按无符号 32 位解析，输出为 JSON 数字。
6. `c/p/K/r` 的 flags 与全部 LSN/时间戳解析后忽略；`S` 的首段标志仅接受
   0/1 且须与历史一致。
